# FE 基本情報技術者試験 対策アプリ

科目A・科目Bの1問1答演習と，分野ごとの正答率にもとづく重点出題を行う Django アプリ。

## 試験の前提（試験要綱 Ver5.6 より）

| | 科目A | 科目B |
|---|---|---|
| 出題数／解答数 | 60問／60問 | 20問／20問 |
| 試験時間 | 90分 | 100分 |
| 形式 | 多肢選択式（四肢択一） | 多肢選択式 |
| 基準点 | 600点／1,000点（IRT） | 600点／1,000点（IRT） |

両科目とも基準点以上で合格。科目Bの分野別出題数は要綱に明記があり，
アルゴリズムとプログラミング16問／情報セキュリティ4問。

## 構成

| ファイル | 役割 |
|---|---|
| `data/categories.py` | 分野・大分類・中分類（全23）のマスタと，科目Aでの想定出題数 |
| `data/questions_*.json` | 同梱の問題バンク（取り込みの初期値） |
| `importer.py` | JSON の検証と一括差し替え |
| `generators.py` | 数値を振り直して作る計算問題のテンプレート |
| `selection.py` | 出題する1問の選定（重点出題のロジック） |
| `stats.py` | 理解度の記録（`record_progress`）と集計 |
| `views.py` | ダッシュボード／演習／分野別正答率／履歴／問題の取り込み |

## 初期セットアップ

`db.sqlite3` はリポジトリに含めていないので、開発環境では作り直す。

```bash
python manage.py migrate --settings=config.settings_dev
python manage.py seed_fe --settings=config.settings_dev
python manage.py createsuperuser --settings=config.settings_dev
```

`seed_fe` が入れるのは**中分類マスタと計算問題のテンプレートだけ**で、問題そのものは入らない。
問題はアカウントごとに持つため、利用者を指定して取り込む。

```bash
python manage.py seed_fe --user <ユーザー名> --settings=config.settings_dev
```

画面からは「自分の問題 → JSONを取り込む → 同梱の問題を取り込む」でも同じことができる。

## 問題の持ち方

**問題はアカウントごと**で、他の人の問題は混ざらない。登録経路は JSON の取り込みだけで、
画面に入力フォームは置いていない。手元の JSON と出題内容がずれないようにするため。

**取り込みは常に一括差し替え**。アップロードしたファイルの内容が、そのままその人の問題集になる。

| | どうなるか |
|---|---|
| ファイルにある問題 | 新しく登録され、出題対象になる |
| これまでの問題 | **削除される**（データが増え続けないように） |
| 解答ログ（`Attempt`） | 問題と一緒に**消える** |
| 分野別の理解度（`CategoryProgress`） | **残る**。正答率・苦手判定・重点出題の土台 |
| 日別の学習記録（`DailyProgress`） | **残る**。学習日数と直近の推移 |
| テンプレートが生成した計算問題 | 触らない（JSON に無くて当然のため） |

解答するたびに、詳細なログとは別に「分野ごとに何問解いて何問正解したか」を
積み上げている。問題を何度入れ替えても、この人の到達点は失われない。

問題ごとの「未出題」「前回まちがえた」と、履歴画面の一覧は差し替えでリセットされる。
問題キーは持たない（照合しないので不要）。

## 問題を追加する

手元の JSON を編集して取り込み直す。

キーは書かない（そもそも持っていない）。

```json
{
  "category": 11,
  "subject": "A",
  "topic": "情報セキュリティ",
  "difficulty": 2,
  "stem": "問題文",
  "choices": ["ア の本文", "イ の本文", "ウ の本文", "エ の本文"],
  "answer": 0,
  "explanation": "解説",
  "source": "出典・根拠"
}
```

- `category` は中分類の番号（1〜23）。`subject` は `A` か `B`。
- `choices` にア／イ／ウ／エの記号は含めない（表示側で付ける）。2〜10個。
- `answer` は 0 始まりの添字。
- 擬似言語のプログラムは `stem` に改行と全角スペースの字下げをそのまま書く。
- 科目Aは四肢択一。**科目Bは本番でも6〜10択が普通**なので、4択にすると易しくなりすぎる。

いま出題対象になっている問題は、画面の「JSONを書き出す」で同じ形式で取り出せる。
書き出して直して取り込み直す、が基本の流れ。

計算問題を増やす場合は `generators.py` の `TEMPLATE_SPECS` に
`(キー, 題材, 中分類番号, 小分類, 生成関数)` を追加する。
生成関数は `stem` / `correct` / `distractors` / `explanation` / `params` を返す。
誤答は3個そろわないと出題されないので，正解と衝突しない候補を多めに並べておく。

## 問題を作るのに必要な資料

**試験の資料はアプリに同梱していない。** 利用者が自分で用意する。
1つの試験につき1つのアプリを作る前提で、対象の試験と必要な資料は `exam.py` に定義し、
ダッシュボード・取り込み画面・プロンプトの3か所へ自動的に反映される。

| 資料 | 何に使うか |
|---|---|
| 試験要綱 | 出題範囲の階層と知識項目例。どの分野に何が含まれるかの根拠 |
| シラバス | 小分類ごとの学習目標と用語例。作問の種 |
| 公開問題（過去問・サンプル） | 実際の設問形式と難易度。転記すれば正解が公式に裏付けられる |

資料を見せずに作らせると、範囲外の問題や誤った正解が混ざる。プロンプトにも
「推測で作らないでください」と明記し、`source`（出典）を必ず書かせている。

別の試験に流用するときは `exam.py` と `data/categories.py` の2つを差し替える。

## 問題を作ってもらうプロンプト

問題は各自が自分の Claude Code に作らせる。プロンプトは `exam.py` の `build_prompt()` が
組み立て、取り込み画面にコピーボタン付きで表示される。含まれるのは次の内容。

- 手元に用意する資料の一覧（`exam.py` の定義から）
- JSON の書式と規則（4択／6〜10択、`answer` は0始まり、記号は入れない など）
- 中分類の一覧と本番での想定出題数（データベースの内容から）
- 誤答の作り方（混同しやすい概念を置く）
- 最後の「【依頼】」の1行。ここを書き換えて分野・問数・科目を指定する

分野を増やしても、試験を差し替えても、プロンプトの内容は定義に追随する。
手で書いた文面を別に持たないので、画面と実物がずれない。

## 重点出題の考え方

1. **中分類を重み付き抽選で選ぶ。** 重みは本番の出題比率（`exam_weight`）を土台に，
   苦手なほど増幅する（`exam_weight × (0.3 + 2.0 × 苦手度)`）。
   本番で8問出るセキュリティを得意になったからといって，
   1問しか出ない法務ばかり出題されては困るため，苦手度だけでは決めない。
2. **苦手度は平滑化した正答率から求める。** 素の正答率だと1〜2問しか解いていない
   中分類が「正答率0％の最重要苦手分野」として暴れるので，事前分布 0.6（基準点相当）へ
   5問ぶん寄せてから比較する（`stats.smoothed_rate`）。
3. **中分類の中では，未出題 → 前回まちがえた問題 → しばらく解いていない問題 の順に選ぶ。**
   計算問題のテンプレートがある中分類では，未出題が尽きたら新しい数値で生成する。

## テスト

```bash
python manage.py test fe --settings=config.settings_dev
```
