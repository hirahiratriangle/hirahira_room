# spec 002：成長基軸（メンバー）

状態：**実装済み** ・ 2026年10月（元資料を受けて確定。未決事項は案のとおり）

## 構想との対応

| 項目 | 内容 |
|---|---|
| 対応するスライド | 5（現場ごとに目標を立て、記録で到達を示す）、13（基本設計フェーズへの入場：目標と到達）、14（genba の記録が到達の証拠になる）、21 のメンバーの列 |
| 立場 | メンバー（本人） |
| 支える判断 | この現場で、どのスキルの、どのレベルを目指すか。何をしたら近づいたと言えるか。振り返りで、到達をどう説明するか |

## 元資料

| 資料 | この spec で使うところ |
|---|---|
| 業務アプリケーション開発 基本設計スキルセット（ITSS対応） | 本書の構成、ITSSの枠組み（11スキル項目）、ITSSのレベル（達成度指標）と複雑性8項目、具体スキル23（具体記述と典型的な場面）、レベル別の具体記述（レベル2〜5）、使い方1〜4、注意点 |

## 書く人の得

- 入場前に「この現場で何を伸ばすか」が一つ決まる。チェックリストの「問われるスキルを選び、目標を立てる」の中身になる
- チェックリストに沿って書いた記録（用語集・まとめ・読めない一覧など）に、スキル項目が自動で付く。**新しく書くことはほぼ増えない**（週報の1行だけ）
- 振り返りのとき、目標ごとに自分の記録が証拠として並ぶ。課会資料・スキルシートにそのまま引ける

## ユーザーストーリー

### US1 入場前に目標を立てる（スライド13「入場前」）

- 担当工程・担当機能から、問われるスキル項目を「典型的な場面」で選ぶ
- 選んだ項目の今のレベルを選び、**一つ上のレベルの具体記述**から目標を選ぶ（例：レベル3のメンバーがレベル4の「画面標準・データモデル・IF方針をチームに示し、レビューで整合させる」を選ぶ）
- 足りないスキルを入場前に準備するメモを書ける
- 目標は現場×本人で持つ。チェックリストの「問われるスキル項目を選び…」の項目から移れる

### US2 記録にスキル項目が付く（スライド14）

記録の種類ごとに、スキル項目を自動で付ける。付け外しは記録の側ではなく、振り返りで証拠を選ぶときに行う（自動で付いたものは候補として上に並び、付いていない記録も証拠に選べる）。

| genba の記録 | ITSS スキル項目 | 基本設計の具体スキル |
|---|---|---|
| 業務フローの図（03_業務理解） | 業務システム構築 | 業務フローの把握と可視化 |
| 用語集 | 業務システム構築 | 業務ドメイン知識の獲得 |
| 「読めない」一覧 | コミュニケーション | 読めない資料の早期の共有 |
| 1週目の「まとめ」 | 知的資産管理活用 | 理解の資料化と再利用 |
| 進捗表の予定と実績 | プロジェクトマネジメント | 担当機能の設計スケジュール管理 |
| 懸念・リスクの Issue（課題） | コンサルティング技法の活用 | リスクの発見と提起 |
| 決裁者・契約範囲の確認（01_契約・02_体制） | ネゴシエーション | 方針と責任範囲の合意 |
| 設計メモ（04_設計） | ソフトウェアエンジニアリング | 影響範囲分析 |

### US3 週報に「目標に近づいた行動」を1行書く（スライド13「期中」）

- 週報に5つ目の欄「目標に近づいた行動」を足す（任意）

### US4 振り返りで到達を説明する（スライド13「振り返り」）

- 目標ごとに、スキル項目が付いた本人の記録が証拠として並ぶ。本人が使うものを選ぶ
- 実際の行動を、レベル別の具体記述に当てはめる（どのレベルの記述に当たるかを本人が選ぶ）
- 評価A〜Eの目安を出す（例：レベル3の記述ならB、後進指導が加わればA）
- ITSSレベル相当を、立場・サイズ・複雑性で説明する欄。社外向けには必ず「相当」と書く
- 課会資料・スキルシートに貼れる文章にまとめて出す
- 「課長と合意した」を記録できる（spec 005 の組織のスキル分布は、合意した到達だけを使う）

## 受け入れ条件（草案）

1. スキルセットの11項目・具体スキル23・レベル2〜5の具体記述・典型的な場面・ITSSのレベルと複雑性8項目が、元資料どおりに引ける（職級・賃金の記述は載せない）
2. 入場前に、項目・今のレベル・一つ上の具体記述を選んで目標を立てられ、チェックリストの項目から移れる
3. 記録の種類に応じてスキル項目が自動で付き、振り返りで証拠の候補として並ぶ（付いていない記録も選べる）
4. 週報に「目標に近づいた行動」を書ける
5. 振り返りで、目標ごとに証拠の記録が並び、具体記述への当てはめ・評価A〜Eの目安・ITSSレベル相当の説明を書ける
6. 課会資料・スキルシートに貼る文章を出せる
7. 他人の目標・到達を一覧にして比べる画面がない（憲章 II・V）
8. デモデータで、スライド5・13・14の内容を画面で説明できる

## 範囲外

- リーダーがまとめを確認し、具体記述に沿って差を返す画面（spec 003）
- 組織のスキル分布、アサイン（spec 005）
- 基本設計以外の工程のスキルセット（同じ形で足す想定）

## 憲章チェック

- [x] I：新しく書くのは週報の1行と、入場前・振り返りの目標だけ。どちらも本人の得になる
- [x] II：人ごとの到達を並べて比べる画面を作らない
- [x] III・IV：目標は現場チーム内、到達の説明は本人だけ
- [x] V：証拠として記録を引くのは本人だけ。他人が拾って評価する機能を作らない
- [x] VI：スキルシートの単価などは扱わない

## 決めたこと

1. ~~元資料~~ → 基本設計スキルセットを反映した。課会資料・スキルシートは書式がないので、目標と到達の文章を貼れる形で出すだけにする
2. **目標と到達の公開範囲**（案のとおり）：目標は現場チームに見せ、到達の説明は本人だけ
3. **評価A〜Eの目安**：元資料の使い方1と「スキルシートの評価A〜E」の対応に合わせる（レベル3の記述ならB、後進指導が加わればA、レベル2ならC）。レベル4以上はレベル3の条件と後進指導を含むのでA
4. **ITSSレベル相当の目安**：立場・サイズ・複雑性からの目安だけ出す（成功回数などの条件は本人が確かめる、と表示する）

## spec 001 から持ち越した論点（案のとおり反映）

1. **チェックリストは人ごと**にする。現場に入った人ごとに、入場時チェックリストを作る
2. **「まとめなし」の危険信号は入場期（入場から4週）だけ**に出す

## 作ってみて分かったこと（構想に戻す）

1. **「課長」は genba の中にいない**：到達の合意は本人が「合意した」と記録するだけ。spec 005 で組織のスキル分布に使うなら、課長が確認できる仕組み（立場として持つか）を決めたい
2. **証拠の候補に週報がすべて並ぶ**：週報にはスキル項目が自動で付かないので、「目標に近づいた行動」を書いた週だけ上に出すなど、絞り方を決めたい
3. **チェックリストの作業は証拠の候補から外した**（12件並んでしまうため）。「進捗表の予定と実績」は、チェックリスト以外の作業だけが証拠になる
