# spec 012：成長の連鎖

状態：**実装済み（階級の必要レベルは案）** ・ 2026年10月

## 構想との対応

| 項目 | 内容 |
|---|---|
| 対応するスライド | 6（個人の成長と会社の成長をつなぐ）、20（組織の力と次のアサイン）、21（立場ごとの成長） |
| 立場 | 全立場 |
| 支える判断 | 成長を階級で報いるか。人の成長が売上を押し上げているか |
| 使うデータ | 承認した成長、終えた作業、階級、月次の人月 |
| 書く人の得 | 入力は増えない。やり遂げた作業がそのまま成長の証拠になり、次の階級への道が見える |

## なぜ作るか

チェックしたところ、「タスクの消化と成長は両輪」「メンバーの成長が会社の成長を決める」が仕組みで切れていた。

1. 成長を承認しても、階級も標準売上も動かなかった
2. 終えた作業が成長の証拠の候補に出なかった
3. 会社の画面が金額から始まり、因果が逆だった
4. 憲章に原則がなかった

## 連鎖

作業をやり遂げる → 成長の証拠にする → 記入・確認・承認 → 階級の見直しの候補 → マネジメントが提案 → 会社が決める → 次に入れる月から標準売上が上がる → 会社が担える仕事が広がる

## 決めたこと

1. 階級は自動で上げない。階級を定めるのは会社の役割で、マネジメントが提案する
2. 過去の月の標準売上は動かさない。人月の行はその月の階級を持つ
3. 見送った提案は、同じ成長では候補に戻らない。次の成長が承認されると候補になる
4. 作業は終えたものだけを証拠の候補にする。チェックリストの作業も含める
5. 会社の画面は、人材開発から始めて、経営の結果を最後に置く
6. 標準売上は、入った時の階級の分と、階級が上がった分に分けて見せる

## 受け入れ条件

1. 承認した成長が提案と採用を通り、次に入れる月の標準売上に届く
2. 提案できるのはマネジメントだけ、決められるのは会社だけ
3. 本人の分は本人に提案させない
4. 終えた作業が証拠の候補に出て、途中の作業は出ない
5. 証拠にした作業がメンバー・リーダー・マネジメントの数字に表れる
6. メンバーに今の階級と次の階級の条件が見える

## 憲章チェック

- [x] II：リーダーとマネジメントの作業の数字は集計だけ
- [x] IV：階級の見直しはマネジメントと会社だけが読む
- [x] V：階級の見直しに使うのは承認した成長だけ

- [x] VII：この spec で足した

## 作ってみて分かったこと（構想に戻す）

1. **必要レベルの決め方**：今はいちばん高い項目のレベルだけを見る。項目の数や ITSS 相当を条件に入れるかは、決めること6の続きとして決めたい
2. **作業の完了だけでは上の数字は動かない**：作業は証拠に使われ、承認されて初めて上に届く。量ではなく成長を見るための形で、意図したもの
3. **階級が下がる場合**：今は上がる方向だけを扱う
