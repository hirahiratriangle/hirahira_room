# plan 001：メンバー支援kit

spec：[spec.md](spec.md)（承認済み。未決事項 2〜4 は spec の案のとおり）

## 方針

- いまのプロトタイプ（v0）のモデルを、テンプレートの構成（docs 00〜07、Issue の種類とラベル）に合わせて組み直す。
- まだ本番に出していないプロトタイプなので、**マイグレーションは `0001_initial` を作り直す**（データの移し替えは書かない）。
- テンプレートの中身（docs の区分、チェックリスト、危険信号、言い回し、ワード確認表）は**コードに持つ**。元資料の docx から `genba/kit_data.py` を生成し、構成の定義は `genba/kit.py` に書く。DB に入れないのは、テンプレートは全現場共通で、版ごとにコードで管理したいから。
- チェックリストは、現場を作った時点で DB にコピーする（作業 Issue とチェック項目）。元資料を改訂しても、作成済みの現場は変わらない（未決事項 4）。

## モデル

| モデル | 変更 |
|---|---|
| `Site` | `started_on` を「入場日」とする。`template_version`（作成時のテンプレートの版）、`is_archived`（Archive 済みは読むだけ）を追加 |
| `Membership` | `joined_on`（その人の入場日。危険信号「5日たってまとめなし」に使う）を追加 |
| `Document` | `kind` を docs の区分にする：`00_pre`〜`07_retro`。週報は `done`・`learned`・`stuck`・`next_step` の4欄（`risks` は廃止） |
| `Term` | `meaning` を空でも登録できるようにする（「意味を確認中」） |
| `Question`（Issue） | ラベル：`scope_out`・`unreadable`（ナレッジ候補は文書・用語の `knowledge_status` のまま。005 で見直す）／読めない：`source`（どの資料）・`location`（どこが）・`reason`（用語・前提・図がない）／懸念：`fact`・`interpretation`・`unconfirmed`・`impact`／作業：`due_on`・`done_on`・`delay_note`／チェックリスト：`stage`・`record_to`・`order` |
| `ChecklistItem`（新規） | 作業 Issue の中のチェック項目。`question`・`text`・`order`・`is_done` |
| `Summary`（新規） | 1週目のまとめ。現場×人で1つ。`overview`・`functions`（本人が書く）、`submitted_at`、`review_note`（リーダーと確かめた結果・期待値との差・2週目の作業） |
| `PromiseCheck` | 変更なし |

## テンプレート（`genba/kit.py`）

- `DOC_SECTIONS`：docs 8区分の名前と「書くこと」（スライド7）
- `ISSUE_KINDS`・`ISSUE_LABELS`：確認事項・課題・作業／スコープ外・読めない・ナレッジ候補
- `LIFECYCLE`：テンプレートから作成 → 記録 → 振り返り → Archive
- `checklist()`：`kit_data.CHECKLIST_STAGES` に、残す場所と「目標を立てる」の1項目（spec 002 への入口）を足したもの
- `create_checklist(site, user)`：現場の作成時に、作業 Issue 12 と項目 45 を作る
- `TEMPLATE_VERSION`：テンプレートの版

## 危険信号（`genba/signals.py`）

`signals_for(user, site)` が、元資料の7つの兆候それぞれに「当てはまるか（判定できるものだけ）」を付けて返す。判定は本人の記録だけを見る（本人のホームにだけ出す。憲章 II）。

| 兆候 | 判定 |
|---|---|
| 3日経っても理解が進んでいない | 本人が書いた「読めない」Issue が3日以上未解決 |
| 指摘も指示も来ない | 入場から1週以上たって、本人の前週の週報がない |
| 理解したことが形になっていない | 本人の入場日から5日以上たって、まとめを出していない |
| ほか4つ | 判定しない（案内だけ） |

## 画面

| URL | 画面 |
|---|---|
| `/genba/kit/` | テンプレート：docs 8区分、Issue の種類とラベル、現場の一生、チェックリスト全体 |
| `/genba/kit/phrases/` | 言い回し集：確認の言い回し8場面、ワード確認表30語（分類ごと） |

| `/genba/sites/<id>/` | 現場のページ。タブ：チェックリスト／Issue／読めない／進捗表／docs／用語集／約束と実際／メンバー。上部に本人の危険信号 |
| `/genba/sites/<id>/issues/create/<kind>/` | Issue を作る。`question`・`unreadable`・`problem`・`task` で欄を変える |
| `/genba/issues/<id>/` | Issue の詳細：チェック項目、予定日・完了日・遅れの理由、解決／再開 |
| `/genba/sites/<id>/summary/` | 1週目のまとめ（自分の分）。本人が書く欄＋記録から自動で並ぶ欄。出す／リーダーと確かめた結果を書く |

| `/genba/member/` | メンバーのホーム：現場ごとのチェックリストの進み具合、危険信号、未解決の Issue、用語集、議事録、検索 |

既存の画面への影響：

- リーダー画面：週報の「課題・リスク」を「詰まっていること」に置き換える
- マネジメント・会社：文書の種類の名前が変わるだけ（会社の「面談メモ」は `00_参画前`）
- 画面の下の約束：「記録で人を採点しない」に改める

## テスト

- テンプレート：現場を作ると 12 Issue・45項目・docs 8区分。`kit_data` に顧客名が入っていない
- 危険信号：3つの判定が、条件の前後で切り替わる。他人の記録では出ない
- 読めない：2日で目安、3日で危険信号
- まとめ：自動の欄に、その現場の用語・未解決の確認事項・読めない一覧だけが並ぶ（他の現場のものは出ない）
- 用語：意味が空でも登録できる。他の現場の同じ語は会社公開分だけ見える
- Archive した現場には書けない
- 既存のテスト（公開範囲、公開レビュー、指標、seed）を新しいモデルに合わせて直す

## デモデータ（`seed_genba`）

- 受発注（自分はリーダー）：入場から10週。チェックリストはほぼ済み、まとめは確認済み
- 保険金請求（自分はメンバー）：**入場から6日**。チェックリストは入場前・初日が済み、1週目が途中。3日止まっている「読めない」があり、まとめは未提出 → 危険信号が2つ出る
- 店舗在庫（自分は入っていない）：マネジメント・会社の画面用
