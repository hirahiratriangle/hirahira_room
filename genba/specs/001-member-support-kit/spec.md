# spec 001：メンバー支援kit

状態：**承認待ち** ・ 2026年10月

## 構想との対応

| 項目 | 内容 |
|---|---|
| 対応するスライド | 7（仕組み）、12（入場時チェックリスト）、15（理解を形にする道具）、16（危険信号） |
| 立場 | メンバー |
| 支える判断 | 今日何を確かめ、誰に聞くか。何が読めていないか。理解を形にして見せられているか |
| 使うデータ（スライド9） | 面談メモ・言葉のズレ／作業範囲・約束事項／用語集／設計メモ／体制・議事録／週報・Issue |
| 公開範囲 | すべて現場チーム内で全文。この spec では会社公開・マネジメント向けの画面は作らない |

## 書く人の得

メンバーが書くものは増えるが、どれも「入場直後に迷わない」ための道具として返ってくる。

- チェックリストに沿えば、最初の2週間に何をすればよいかが分かる
- 「読めない」を残すと、2日動かないときに質問へ進むきっかけになる
- 用語集・読めない一覧・未解決の質問が、そのまま1週目の「まとめ」の材料になる（書き直さなくてよい）
- 言い回し集で、期待値・決裁者・契約外の依頼をどう切り出すかに迷わない

## ユーザーストーリー

### US1 現場をテンプレートから作る（スライド7）

現場を作ると、テンプレートどおりの構成がその現場に並ぶ。

- docs の区分：`00_参画前`、`01_契約・条件`、`02_体制`、`03_業務理解`、`04_設計`、`05_議事録`、`06_週報`、`07_振り返り`
  - 各区分に「書くこと」を表示する（例：`01_契約・条件` は「作業範囲と約束事項（金額は置かない）」）
- Issue の種類：確認事項・課題・作業
- Issue のラベル：スコープ外・読めない・ナレッジ候補
- 現場の一生：テンプレートから作成 → 記録 → 振り返り → Archive（状態として持つ。Archive した現場は読むだけ）

### US2 入場時チェックリストに沿って動く（スライド12）

現場を作ると、入場時チェックリストの項目がその現場の「作業」Issue として段階ごとに並ぶ。

| 段階 | ねらい | 項目（初版） | 残す場所 |
|---|---|---|---|
| 入場前 | 契約と現場の進め方のずれを、言葉で確かめる | 契約形態と指示の出され方／担当工程と期待値／自社の相談先と報告サイクル／問われるスキルを選び、目標を立てる | 00_参画前・01_契約 |
| 初日 | 組織図と実際の決裁の流れを一枚にする | 体制と決裁者、質問する相手／資料の置き場所と最新版／進捗表を作り、確認作業を最初のタスクに | 02_体制・作業 Issue |
| 1週目 | 担当機能と全体像を、自分の言葉で説明できる | 全体像を一枚の図に／読めない箇所の一覧／5日目に「まとめ」を出し、リーダーと15分 | 03_業務理解・04_設計 |
| 2週目以降 | 進捗と懸念を、聞かれる前に出す | 週1回の短い共有／自分で決める範囲の線を引く／懸念は事実・解釈・未確認に分ける | 06_週報・課題 Issue |

- メンバーは、段階ごとの進み具合（済み／全体）を自分の現場のページで見られる
- 各項目から、残す場所（docs の区分や Issue の作成画面）へ移れる
- 「問われるスキルを選び、目標を立てる」は項目として並べるだけ。目標の中身は spec 002 で作る

### US3 「読めない」を残す（スライド15・16）

- 「読めない」ラベルの Issue に、**どの資料の・どこが・なぜ読めないか**（用語／前提／図がない／その他）を書ける
- 現場のページに「読めない」一覧を出す
- 2日動かない（解決もコメントもない）項目には「質問へ進む」目安を出す

### US4 1週目の「まとめ」を組み立てる（スライド15）

- 「まとめ」は、**全体像の図**（文章か図へのリンク）・**担当機能**を本人が書き、**用語集**・**未解決の質問**・**読めない一覧**はその現場の記録から自動で並べる
- まとめを「出した」状態にできる（チェックリストの「5日目に『まとめ』を出す」と連動）

### US5 週報と懸念を型で書く（スライド15・16）

- 週報は **やったこと・分かったこと・詰まり・次** の4欄（対象週は月曜にそろえる）
- 課題 Issue は、懸念を **事実・自分の解釈・未確認のこと・影響** に分けて書ける（人ではなく事実と影響を書く、という注意を表示する）

### US6 用語集とズレの確認（スライド15）

- 分からない語も、意味を空のまま載せられる（「意味を確認中」と表示）
- 「一般的な意味との違い」を書ける（用語のズレ）
- 同じ語が他の現場でどう使われたかを引ける（他の現場の分は、会社公開されたものだけ）

### US7 言い回し集（スライド15）

- 場面ごとに、そのまま使える一言を引ける。初版の場面：期待値を聞く／決裁者を確かめる／契約外の依頼を保留する／読めない箇所の説明を頼む／進捗と理解を見せる
- 言い回し集はテンプレート側（全現場共通）に持つ

### US8 危険信号（スライド16）

メンバーのホームに、いまの記録から当てはまる兆候と「その日にやること」を出す。

| 兆候 | 判定（プロトタイプ） | その日にやること |
|---|---|---|
| 3日経っても理解が進まない | 「読めない」Issue が3日以上未解決 | 読めない箇所の一覧を作り、質問の時間を頼む |
| 指摘も指示も来ない | 週報が前週に出ていない | 「問題ない」と受け取らず、進捗と理解を見せる |
| 理解が形になっていない | 入場から5日以上たって、まとめを出していない | 小さくても「まとめ」を作って共有する |
| 日々の指示者が体制図と違う | 判定しない（案内だけ） | 実際の決裁の流れをメモし、自社に共有する |
| 契約にない作業・責任を頼まれる | 判定しない（案内だけ） | その場で引き受けず、自社の課長に相談する（スコープ外 Issue） |

## 受け入れ条件

1. 現場を作ると、docs 8区分・チェックリスト13項目（4段階）がその現場に並ぶ
2. メンバーは段階ごとのチェックリストの進み具合を見て、項目を済みにできる
3. 「読めない」Issue を作ると一覧に出て、2日動かないと目安が、3日で危険信号が出る
4. まとめの画面に、本人が書いた欄と、用語集・未解決の質問・読めない一覧が並ぶ
5. 週報は4欄、課題 Issue は懸念の型で書ける
6. 意味が空の用語を登録でき、他の現場の会社公開された同じ語が見える（会社公開されていない語は見えない）
7. 言い回し集を場面ごとに引ける
8. 危険信号が、条件に当てはまるときだけメンバーのホームに出る
9. 画面の約束の文言を「記録で人を採点しない」に改める
10. デモデータで、スライド7・12・15・16の内容を画面で説明できる

## 範囲外

- GitHub のテンプレートリポジトリ・同期（プロトタイプでは作らない）
- 目標・スキル項目・到達（spec 002）
- リーダーの受け取り画面（「読めない」の受け取り、まとめ確認など。spec 003）
- 体制のズレの件数など、マネジメント向けの数字（spec 004）
- 公開範囲の見直し（本人に選ばせない形への変更。spec 005）
