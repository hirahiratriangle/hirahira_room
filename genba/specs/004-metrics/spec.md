# spec 004：運営指標（マネジメント）

状態：**実装済み** ・ 2026年10月

## 構想との対応

| 項目 | 内容 |
|---|---|
| 対応するスライド | 18（マネジメント：現場単位の指標で、手を打つ現場を決める）、16（日々の指示者が体制図と違う → 体制のズレとして記録） |
| 立場 | マネジメント（課長） |
| 支える判断 | どの現場に手を打つか。営業時の説明と実態がずれていないか |
| 使うデータ（スライド9） | 現場単位の集計値だけ（原文・個人名は見せない） |

## 指標（スライド18の6つ＋spec 003 で決めた2つ）

| 指標 | 定義（案） | 気づけること |
|---|---|---|
| 確認事項の滞留日数 | 未解決の確認事項の経過日数の平均 | 現場の意思決定が止まっている |
| 約束と実際のズレ | 振り返りの「約束と実際」で食い違った行の数 | 営業時の説明と実態の乖離 |
| スコープ外の件数 | 「スコープ外」ラベルの Issue 数 | 追加交渉・契約見直しが要る |
| **体制のズレ**（追加） | 実際の指示者・決裁者が体制図と違う件数 | 契約形態と指示系統の不一致 |
| 用語のズレ | 一般と意味が違う用語の数 | 立ち上がりの難しさ |
| 週報の提出率 | 週報がある週の割合（現場単位） | 運営が回っているか |
| **リーダーの懸念**（決定 1） | 現場のリーダーが書いた未解決の懸念の数（うちメンバーがまだ受け取っていない数） | リーダーが一人で抱えている |
| **週報の途切れが続いている**（決定 2） | 前週から2週以上続けて週報が出ていない人の**人数**（名前は出さない） | 「指摘も指示も来ない」状態が続いている |

### 使わない指標（変更なし）

個人のコミット数・記述量／個人別の稼働時間の比較／振り返りの文章による個人評価

## 決めたこと（spec 003 の論点）

1. **リーダー自身の懸念**：メンバーへは**フィードバック**として見せ（現場のページとメンバーのホームに「リーダーからの懸念」として出し、メンバーが受け取って返事を書ける）、マネジメントへは**指標**として届ける（件数だけ）
2. **週報の途切れ**：リーダーにだけ出す。**2週以上続いたら**マネジメントにも届ける（人数だけ）

## ユーザーストーリー

- US1 体制のズレを記録する：危険信号「日々の指示者が体制図と違う」から、「体制図では誰か／実際は誰か（指示者か決裁者か）」を記録する（現場のページの「体制のズレ」タブ）
- US2 マネジメントは、現場ごとの8指標を一覧で見て、目安を超えた現場から手を打つ
- US3 指標ごとの定義と「気づけること」を画面に出す（定義はすべて案）
- US4 メンバーは、リーダーの懸念をフィードバックとして見て、受け取りの返事を書ける
- US5 リーダー画面に、週報の途切れが続いているメンバーは「マネジメントにも届いている」と出す

## 受け入れ条件

1. 体制のズレを記録でき、危険信号から移れる
2. マネジメントの画面に8指標が現場ごとに出て、目安を超えた値と「気づけること」が出る
3. マネジメントの画面に、原文・個人名（記録の中身、週報が途切れている人の名前）が出ない
4. リーダーの懸念がメンバーに見え、リーダー以外のメンバーが受け取れる。リーダーは自分の懸念を受け取れない
5. 週報が2週以上続けて途切れると、マネジメントの指標に人数が出る。1週だけなら出ない
6. デモデータで、スライド18の内容を画面で説明できる

## 憲章チェック

- [x] I：メンバーが新しく書くのは体制のズレだけで、危険信号の「その日にやること」の記録になる
- [x] II：すべて現場単位。週報の途切れは人数だけ、リーダーの懸念は件数だけ
- [x] IV：マネジメントは集計値だけ（到達の合意は spec 002 で本人が依頼したものだけ）
- [x] V：指標で人を採点しない

## 作ってみて分かったこと（構想に戻す）

1. **人数が少ない現場では、人数でも人が分かる**：「週報の途切れが続いている：1人」は、メンバーが2〜3人の現場では誰のことか推測できる。人数を出すのを一定人数以上の現場に限るか、「いる／いない」だけにするかを決めたい
2. **リーダーの懸念は、リーダーが1人の現場ではリーダー個人の数字になる**：指標としては「現場に未受け取りの懸念がある」の方が、個人を測らない原則に近いかもしれない
