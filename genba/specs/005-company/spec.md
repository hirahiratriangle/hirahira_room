# spec 005：会社（ナレッジ資産と成長のつながり）

状態：**実装済み** ・ 2026年10月

## 構想との対応

| 項目 | 内容 |
|---|---|
| 対応するスライド | 6（個人の成長と会社の成長を同じ物差しでつなぐ）、19（現場をまたいで再利用できる記録を残す）、20（個人の到達を組織の力と次のアサインに変える）、21（立場ごとに成長の視点が違う） |
| 立場 | 会社（ナレッジ資産）。公開レビューはリーダー、改訂の提案は誰でも |
| 支える判断 | 何を資産として残し、提案・見積・育成にどう使うか。次に狙う案件と、誰をどの現場へアサインするか |
| 使うデータ（スライド9） | 一般化して公開された記録（面談メモ・用語集・設計メモ・振り返り）、課長と合意した到達（匿名の集計）、本人が出したアサインの希望 |

## 憲章 III に合わせた公開レビューの見直し

いまのプロトタイプは「本人が公開に切り替える」形で、憲章 III（本人に公開範囲を選ばせない。会社へは一般化レビューを通して出す）とずれている。次の形に改める。

1. 現場チームの誰でも、公開できる記録（00_参画前・04_設計・07_振り返り・用語）に「ナレッジ候補」を付けられる
2. リーダーが**一般化した版**（顧客名を業界名に、固有の業務名・システム名を一般化、個人が特定できる記述を外す）を書いて公開する（決めること2：仮にリーダー）
3. 会社に見えるのは**一般化した版だけ**。原文は現場チームの中に残る。リーダーは公開をやめられる

## ユーザーストーリー

### US1 公開レビュー（スライド19「公開の流れ」）
- 候補を付ける → リーダーが一般化した版を書いて公開 → 会社の画面には一般化した版と業界名だけが出る

### US2 ナレッジ資産（スライド19の6つ）
| 資産 | プロトタイプでの作り |
|---|---|
| 業界別の用語辞書 | 公開された用語を業界ごとに合算 |
| 設計判断の先例 | 公開された設計メモ（案・決定・理由）を検索 |
| 営業・面談の質問リスト | 公開された振り返り（約束と実際）から、入場前に確かめる質問を会社の立場で足していく |
| チェックリストの改訂／言い回し集／成長の物差しの更新 | 誰でも「改訂の提案」を出せ、会社の立場が採用・見送りを決める（テンプレートはコードで版を管理しているので、採用したものは次の版で反映する） |

### US3 組織のスキル分布と次のアサイン（スライド20）
1. **組織のスキル分布**：ITSS 11項目 × レベルの人数分布。課長と合意した到達だけを匿名で集計する
2. **次に狙う案件を決める**：合意した到達の ITSS レベル相当（担える立場・規模）と、経験した複雑性の項目を集計する
3. **目標に合う現場へアサイン**：本人が到達のあとで「次の目標（一つ上の列）」を書き、**アサインの希望として会社に出す**と選んだものだけが会社の画面に並ぶ
4. **育成への再投資**：レベル3以上の人数が少ない項目を「薄い項目」として出し、ナレッジ・チェックリスト・勉強会につなげる

### US4 成長のつながり（スライド6・21）
- ITSS の達成度（責任性・複雑性・サイズ・プロフェッショナル貢献）と、個人の成長・会社の成長の対応表、成長のループ
- 4つの立場ごとの成長の視点（目安と証拠）
- リーダーの証拠として、まとめへの返し（後進の指導）を証拠の候補に足す

## 受け入れ条件

1. 本人が会社公開に切り替える操作がない。公開はリーダーが一般化した版を書いて行い、会社の画面には一般化した版だけが出る（原文・現場名・個人名は出ない）
2. 業界別の用語辞書・設計判断の先例・振り返り・面談メモ・営業・面談の質問リストが会社の画面に出る
3. 誰でも改訂の提案を出せ、会社の立場が採用・見送りを決められる
4. 組織のスキル分布は合意した到達だけを数え、名前を出さない。合意していない到達は数えない
5. アサインの希望は、本人が出したものだけが会社の画面に出る
6. 薄い項目、ITSSレベル相当の分布、経験した複雑性が出る
7. 成長のつながり（スライド6・21）が画面で説明できる
8. デモデータで、スライド6・19・20・21の内容を画面で説明できる

## 憲章チェック

- [x] II：スキル分布は人数だけ。人を並べて比べない
- [x] III：本人に公開範囲を選ばせない。会社へは一般化レビューを通したものだけ
- [x] V：分布に使うのは合意した到達だけ。アサインの希望は本人が出したものだけ
- [x] VI：一般化で顧客名・固有名を外す

## 作ってみて分かったこと（構想に戻す）

1. **一般化レビューの担い手**（決めること2）：プロトタイプではリーダーが一般化した版を書いて公開する。リーダーが一人で抱えると候補が溜まるので、会社の立場が一般化を手伝うか、粒度（どこまで固有名を外すか）の基準を決めたい
2. **少人数のスキル分布**：合意した到達が少ないうちは、項目×レベルの人数でも誰か推測できる。一定人数に満たないセルは「少数」とだけ出すかを決めたい（spec 004 の論点1と同じ）
3. **アサインの希望は個人名で会社に出る**：本人が出したものだけだが、組織のスキル分布（匿名）とは性格が違う。誰が見られるか（会社の立場の範囲）を決めたい（決めること4）
4. **改訂の提案は採用してもテンプレートに自動で入らない**：テンプレートはコードで版を管理しているため。採用した提案を次の版に入れる手順（誰が元資料を直し、データを生成し直すか）を決めたい
