# spec 015：資産ベースの KPI

状態：**実装済み（KPI と目標はすべて案）** ・ 2026年11月

## 構想との対応

| 項目 | 内容 |
|---|---|
| 対応するスライド | 18（会社：ナレッジ資産） |
| 立場 | 会社。マネジメントにも会社の KPI として見える |
| 支える判断 | 経験が会社に残っているか、どの資産へ手を入れるか、資産が次の現場の人を支えているか |
| 使うデータ | 公開中の記録、質問リスト、採用した改訂提案、文書が別の現場で開かれた日 |
| 書く人の得 | メンバーの入力は増えない。書いた記録が別の現場で使われたことが、会社の数字に表れる |

## なぜ作るか

ナレッジ管理の KPI は公開の増分と業界カバー率で、流れを見ている。スライド18の6つの資産がどれだけ貯まり、使われているかは見えなかった。溜まっているだけの記録は資産と呼べないので、活用も測る。

## KPI（案）

| KPI | 定義 | 目標（案） |
|---|---|---|
| ナレッジ資産の残高 | 公開中の用語と設計判断、質問リスト、採用した改訂提案の合計 | 直近3か月に5件以上増える |
| 育っている資産 | 6種類のうち、直近3か月に増えた種類の数 | 3種類以上 |
| 別の現場で開かれた文書 | 書いた現場の外の人に開かれた公開文書 ÷ 公開文書 | 50%以上 |

## 決めたこと

- 金額には換算しない。実際の金額を置かない方針で、資産の値段を決める根拠もない（憲章 VI）
- 活用は「開かれた」ことだけを数える。役に立ったかは分からない
- 開いた人は記録しない（憲章 II）。文書ごと1日1行で、再読み込みでは増えない
- 書いた現場の人と、現場に入っていない会社の立場は数えない
- 用語は詳細の画面がないので活用を測らない
- 改訂の提案は採用した日を持たないので、提案した日で増分を数える

## 憲章チェック

- [x] I：入力欄を足さない
- [x] II：人ごとの数字を返さない。開いた人を持たない
- [x] IV：公開中の記録と、会社が扱うものだけを数える
- [x] VI：金額に換算しない
- [x] VII：資産の数字は、現場の記録と公開レビューから説明できる
