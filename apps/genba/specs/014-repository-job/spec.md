# spec 014：リポジトリを職種で分ける

状態：**実装済み（プログラマーのチェックリストは案）** ・ 2026年11月

## 構想との対応

| 項目 | 内容 |
|---|---|
| 対応するスライド | 2（GitHub との対応）、スキル台帳 |
| 立場 | メンバー、リーダー、会社 |
| 支える判断 | その人に合うテンプレートはどれか。職種ごとの人とスキルの厚みはどうか |
| 使うデータ | リポジトリの職種、入場時チェックリスト、承認した成長 |
| 書く人の得 | 職種を1つ選ぶだけで、自分の工程に合うチェックリストが並ぶ |

## なぜ作るか

テンプレートは「入場時チェックリスト上流編」と基本設計スキルセットだけで、SE の現場を前提にしている。プログラマーが入ると、確かめる項目が自分の仕事に合わない。

## 決めたこと

- リポジトリは1人に1つのまま（憲章の GitHub との対応）。職種ごとにリポジトリを持たせると、プログラマーから SE に上がったときに記録が切れる
- 職種はリポジトリに持つ。現場を作るときに選び、メンバーのホームで変えられる。マネジメントのアサインでは今の職種のまま入る
- 職種を変えても作成済みの現場のチェックリストは変えない。次に入る現場から効く（テンプレートの版と同じ考え方）
- リポジトリ名は変えない
- 既存のリポジトリはすべて SE とする
- 職種を、人を比べる数字に使わない。運営指標には出さず、現場のメンバー一覧とスキル台帳でだけ使う

## プログラマーのテンプレート

元資料に製造編はないので、上流編のうち上流に固有の項目だけを差し替えた案である。段階・小見出し・残す場所は SE と同じ。

スキルセットは基本設計のものだけで、プログラマー向けの具体スキルとレベルの記述はまだない。ITSS の11項目は職種をまたいで使えるので、目標と成長の流れは同じものを使う。

## 画面

- テンプレート：SE とプログラマーのチェックリストを切り替えて読む。最初に開くのは本人の職種
- メンバーのホーム：リポジトリ名の横で職種を変える
- 現場を作る：職種を選ぶ。本人の今の職種が最初から選ばれている
- 現場のメンバー一覧：職種を出す
- 会社のスキル台帳：全員・SE・プログラマーで切り替える
