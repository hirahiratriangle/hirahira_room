# spec 010：リーダーの職掌とKPI

状態：**実装済み（KPI と目標は案）** ・ 2026年10月

## 構想との対応

| 項目 | 内容 |
|---|---|
| 対応するスライド | 17（リーダー画面）、21（立場ごとの成長）、22（成長の確定） |
| 立場 | リーダー |
| 支える判断 | 今日、誰が何で止まっているか。メンバーへ何を返すか。何を会社へ公開するか |
| 使うデータ（スライド9） | 自分の現場の記録の集計（現場チームの範囲） |
| 書く人の得 | メンバーが書く量は増えない。既にある記録から数える |

## マネジメントとの違い

マネジメントは現場をまたいで、どこに手を打つかを決める。リーダーは1つの現場の中で、メンバーが止まらないように日々支える。

| 観点 | マネジメント | リーダー |
|---|---|---|
| 問い | どの現場と誰に手を打つか | 今日、誰が何で止まっているか |
| 決めるもの | 手を打つ現場、成長の承認、アサイン | 説明の時間、裁量の線、公開する記録 |
| 見る単位 | 全現場 | 自分の現場の、一人ひとり |
| 時間の幅 | 週〜月 | 日〜週 |
| 成長への関わり | 承認する | 事実を確認する |

## 職掌（案）

| 職掌 | 責任を持つこと | KPI | 目標（案） |
|---|---|---|---|
| 詰まりの解消 | 読めない資料や確認事項を、止まる前に解く | 確認事項の平均滞留日数 | 7日未満 |
| | | 説明の時間を割り当てた割合 | 80%以上 |
| メンバーの育成 | まとめに返し、成長を事実で確認する | まとめに返した割合 | 80%以上 |
| | | 成長の確認待ち | 2件以下 |
| チームの運営 | 週次共有を回し、裁量の線を言葉にする | 週報の提出率 | 75%以上 |
| | | 裁量の線を書いた人 | 80%以上 |
| 知見の資産化 | ナレッジ候補を一般化して会社へ公開する | 公開待ちの候補 | 3件以下 |

## 決めたこと

1. 数字は現場単位で、人を比べない。人ごとの状況は今のリーダーの画面で見る
2. このKPIはリーダー自身の振り返り用で、マネジメントと会社には渡さない。リーダーが1人の現場では、現場の数字がリーダー個人の数字になるため
3. ひとり現場にはこの画面を出さない。確認はマネジメントが担う
4. 複数の現場を持つリーダーには、現場ごとに分けて出す

## 受け入れ条件

1. リーダーの `/genba/kpi/` に、動いている現場ごとの4職掌が先に出て、全社の数字は参考として下に出る
2. メンバーとマネジメントの画面に、この4職掌は出ない
3. 画面にメンバーの名前が出ない
4. リーダー本人の記録は、割合に数えない

## 作ってみて分かったこと（構想に戻す）

1. **リーダーの成長の証拠**：スライド21では、詰まりの解消やメンバーの成長がリーダーの証拠になる。このKPIを評価に使うかは、上に渡さない今の決めと合わせて決めたい
2. **数の少ない現場**：メンバーが1〜2人だと、割合が大きく動く。目標の達成・未達は目安として読む
