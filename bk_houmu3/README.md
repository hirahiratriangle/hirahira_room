# 銀行業務検定 法務3級 対策アプリ

五答択一の1問1答演習と，区分ごとの正答率にもとづく重点出題を行う Django アプリ。
基本情報版（`fe/`）を雛形に作った。出題ロジック・ID・学習モード・取り込みの作りは同じで，
試験に合わせて変えたのは下の「基本情報版との違い」のところだけ。

## 試験の前提

- 1回50問・五答択一式の1科目（問題解説集の各回の収録から）。試験時間と合格基準は，
  協会の実施要項で確かめる（手元の問題解説集では実施要項のページが読めていない）
- 出題範囲は預金・融資・内国為替・銀行取引関連法の4分野。2026年度から
  「手形法・小切手法」が外れ，「証券取引」「金融犯罪」が新設される

## 基本情報版との違い

| | 基本情報版 | 法務3級版 |
|---|---|---|
| 分類 | 科目A 23中分類・科目B 5項目 | 1科目・22区分（`data/categories.py`）。問題解説集の「出題項目一覧」の区分 |
| 想定出題数 | 公開問題140問の実測（60問） | 過去5回250問の実測（50問）。手形法・小切手法は0問（範囲外） |
| 選択肢 | ア〜エ | (1)〜(5) |
| 出典のラベル | IPA公開問題／IPAサンプル問題／自作／自動生成 | 過去問（「2025年10月 第162回 問2」で始まるもの）／練習問題／自作 |
| 出題モード | 「IPA公開問題から」「計算問題を」あり | 「本試験の過去問から」に変え，計算問題のモードは出さない（型が無い） |
| 取り込みの鍵 | 科目＋中分類＋問題文 | 科目＋中分類＋問題文＋**出典の回・問番号**（下の節） |
| 科目の欄 | 科目A／科目B を選ぶ | 出さない（値は A で固定） |

内部の名前（`MODE_IPA`，`from_ipa`，`subject` の項目など）は，基本情報版との差を小さく
保つためにそのまま残してある。

## 初期セットアップ

`db.sqlite3` はリポジトリに含めていないので、開発環境では作り直す。

```bash
python manage.py migrate --settings=config.settings_dev
python manage.py seed_bk_houmu3 --settings=config.settings_dev
python manage.py createsuperuser --settings=config.settings_dev
```

`seed_bk_houmu3` が入れるのは**中分類マスタだけ**（法務3級に計算問題のテンプレートは無い）。
**問題は同梱していない。** 管理用の ID で入り、画面の
「問題の管理 → JSONを取り込む」から取り込む。

**すべての画面で hirahira_room へのログインが要る。** サイト全体は
`LoginRequiredMiddleware` でログイン必須で、基本情報版は学習の画面を `login_not_required` で
外しているが、法務3級版は外さない。問題が市販の問題解説集からの転記なので、
ログインせずに読めてはいけないため。ログインしたうえで、`/bk_houmu3/` で本アプリの中の ID（`Learner`）を入力するか新しく作る。
成績はアカウントではなく、**この ID ごと**に持つ。

入った ID は、**ブラウザを閉じたら抜ける**。セッションに加えて、期限の無い Cookie
（`bk_houmu3_learner`）にも ID を置き、それが消えていればセッションに残っていても入口に戻す。
セッションはブラウザを閉じても2週間残るので、それだけだと共用の端末で次の人が
前の人の ID のまま入ってしまう。Safari の「前回のウインドウを開き直す」のように、
ブラウザが閉じる前の Cookie を戻す設定では残ることがある。

問題の管理だけは、管理用の ID に加えて、**スタッフ権限（`is_staff`）のある
アカウント**での hirahira_room へのログインも要る（`AdminRequiredMixin`）。
ID には合言葉がなく、アカウントも誰でも作れるので、どちらも「本人である」ことの
証明にならない。スタッフ権限は Django の管理画面の「ユーザー」でしか付けられない。

管理用の ID は、画面からは作れない。ID を一度作ってから、Django の管理画面の
「法務3級 学習者ID」で「管理用」（`is_admin`）に印を付ける。

## 問題の持ち方

**問題は同梱しない。リポジトリにも本番にも入れない。** 問題は市販の問題解説集
（経済法令研究会『法務3級 問題解説集 2026年度受験用』）からの転記で，著作物のため，
手元の開発環境にだけ取り込んで使う。本番の hirahira-room では問題 0 問のままにしておく。

問題 JSON は，本書の OCR（`全文_OCR.txt`）から組み立てスクリプトで作る。どちらもリポジトリの外，
本書の PDF のそばに置いてある（`問題集/作業中/build_questions.py`）。

- 正解は「正解：（N）」の行と，解説の「これが本問の正解」の二つから取り，食い違えば止める
- 区分（中分類）は見出し＝出題項目で「出題項目一覧」から引く。小分類は出題項目そのもの
- 難易度は正解率から（70%以上 1・40%以上 2・それ未満 3）
- 表・カレンダー・囲みで読み順が崩れた問は，紙面から起こし直した文で置き換えている

取り込みは基本情報版と同じく同期（追加・更新・削除）で，問題の管理画面から行う。

### 取り込みの鍵に出典の回・問番号を入れている

法務3級は，同じ問いかけ（「預金保険制度について，誤っているものは次のうちどれですか。」）が
回をまたいで何度も出て，選択肢だけが違う。基本情報版の鍵（科目・中分類・問題文）のままだと
別の問題が同じ鍵になり，取り込みで弾かれる（250問中38組）。そこで出典の「回と問番号」を
鍵に足した。出典の後ろの括弧（正解率）は鍵に入れないので，正解率を直しても同じ問題の更新になる。

## みんなの集計

ダッシュボードの下のほうに、全 ID を合わせた数字を出す。ID ごとの成績や ID は出さない。

解答の記録をこの集計と問題の改善に使うこと、運営が ID ごとの記録を見られることは、
入口（`start.html`）と ID の切り替え画面（`enter.html`）の注意書きの下に書いてある。
アプリが持つのは ID だけで人とは結びつかないので、「個人が分からない」ではなく
「ID ごとの成績が分からない」と書く。

| 項目 | 何から数えるか |
|---|---|
| のべ解答数・正答率 | 全 ID の `CategoryProgress` の合計。取り込み直しても減らない |
| 分類別・分野別 | 同じく `CategoryProgress` を分類ごとに合計。分野（預金・融資など）ごとにも合計 |
| 学習した人 | 1問以上解いた ID の数 |
| 合格者数 | `PassReport`（本番合格の自己申告）の件数。1つの ID につき1件で、取り消せる |

合格は本人の申告をそのまま数える。本番の結果とは照合できない。

## 重点出題の考え方

基本情報版と同じ。重みは `exam_weight × (0.3 + 2.0 × 苦手度)`，苦手度は正答率を 0.6 へ
5問ぶん寄せて平滑化してから求める。中分類の中では，未出題 → 前回まちがえた問題 →
しばらく解いていない問題 の順に選ぶ。想定出題数が 0 の手形法・小切手法は，おまかせと
本番比率どおりでは出ず，分野を指定したときだけ出る。

## テスト

```bash
python manage.py test bk_houmu3 --settings=config.settings_dev
```

重点出題が実際に苦手分野へ寄るかどうかは統計的に検証している（`SelectionTests`）。
基本情報版のテストを法務3級の分類に置き換えて引き継ぎ，科目B・計算問題のテンプレート・
IPA の出典に固有のものは外した。
